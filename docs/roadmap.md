# 로드맵

AI가 고친 C++ 게임 서버 코드를 **사람이 흐름으로 확인**하는 데 필요한 기능을 단계별로 만든다.
웹 API 개념(라우트, 미들웨어, 컨트롤러)이 아니라 게임 서버 개념(패킷, 프로세스 간 중계, 레인)을 기준으로 한다.
순서는 "AI가 고친 코드를 리뷰한다"는 목적에 가까운 것부터.

## 완료

- [x] v1: 진입점(패킷 핸들러) → 호출 트리 → 코드 스택
- [x] 보기 방식 3가지: 트리 / 노드 / 노드 크게
- [x] 폴더로 대상 추가(설정 자동 생성)

## 1단계 — 리뷰 기본기 (AI 수정 확인에 바로 쓰임) ✅ 완료

| 기능 | 내용 | 상태 |
|---|---|---|
| 편집기에서 열기 | 코드 스택의 "열기"·줄 번호 → Visual Studio / VS Code 의 그 줄 | ✅ |
| 신선도 표시 | 분석한 입력 파일 지문(크기·시각·해시) 저장 → 최신/바뀜/확인 불가 배지, 30초마다 확인, 바뀐 파일의 코드 스택 경고 | ✅ |
| 변경 영향 찾기 | 이 함수를 바꾸면 영향받는 **패킷**(호출자 역추적 → 진입점)과 대표 경로, 경로를 코드 스택으로 열기 | ✅ |
| 수정 전후 비교 | 직전 분석 자동 보관 + 기준 저장. 진입점·함수(본문/시그니처/추가/삭제)·호출 변화, 이름 변경 후보 | ✅ |
| 디스패처·가상 함수 연결 | `X.Dispatch` → 같은 파일 `X.Register` 핸들러(등록 연결, 추정), 가상 함수 구현 후보(추정) | ✅ |

남은 것: 디스패처가 레인(다른 스레드)을 거쳐 호출되는 경로는 3단계 "패킷 여정"에서 잇는다.

## 2단계 — AI 연동 ✅ 완료

| 기능 | 내용 | 상태 |
|---|---|---|

## 3단계 — 게임 서버 보기

| 보기 | 내용 |
|---|---|
| 패킷 여정 | 클라 → Gateway 중계 → World 라우팅 → Zone 처리. `SendPacket(X)` 과 X 의 핸들러를 패킷 id 로 이어 **프로세스를 넘는 흐름** |
| 시작 흐름 | `main` → `App::Init` 순서: 설정 로딩, 스레드·레인 구성, 핸들러 등록, 리스너 |
| DB와 캐시 | SP·`DbCommand` 호출, `UnitOfWork` 태스크, 캐시 갱신 순서 |
| 전체 흐름도 | 서버 × 클래스 지도, 패킷이 어떤 클래스를 거치는지 |
| 클래스 다이어그램 | clangd 타입 계층·멤버로 UML |

## 4단계 — 점검 규칙

게임 서버 규칙을 대상 설정(`targets/*.json`)으로 켠다.

- 보상 처리: 재화 차감 → 지급 실패 시 남는 것
- 대상별 불변 규칙(설정으로 켬, 예: 모델 변경이 `UnitOfWork` 에 Task 로 안 들어간 경로, 공용 라이브러리가 콘텐츠에 의존)
- 스레드: 레인 밖에서 게임 상태 접근, 락 안에서 I/O
- 모든 점검에 근거(파일:줄)와 확실도, 돌지 않은 규칙은 "꺼짐"으로 남김
