1. 실행하기

개발 PC (소스로 실행)

필요한 것: .NET 10 SDK. C++을 분석하려면 LLVM(clangd)과 Visual Studio C++ 도구도 필요합니다.

cd D:\Work\RockQ\Projects\review-tool
.\run.ps1             # 빌드 → 서버 시작 → 브라우저로 http://127.0.0.1:5057 열기
.\run.ps1 -Analyze -Target asio-server   # 화면 없이 분석만

끝낼 때는 실행한 창에서 Ctrl+C를 누릅니다.

설치 없이 (데스크톱 exe 하나)

.\tools\publish-desktop.ps1     # → dist\review-tool.exe (약 61MB)
  • .NET 런타임이 exe 안에 들어 있어 설치할 것이 없습니다. 화면은 Windows 11에 기본으로 있는 WebView2로 띄웁니다.
  • 대상 설정과 분석 결과는 exe 옆의 targets\, data\에 생깁니다.
  • 결과 보기와 C# 분석에는 추가로 필요한 것이 없습니다. C++ 다시 분석에는 LLVM과 VS C++ 도구가 따로 있어야 합니다.
  • review-tool.exe --self-test를 실행하면 창을 띄우지 않고 화면 파일이 잘 나오는지만 확인합니다.
화면 서버는 이 PC(127.0.0.1)에서만 접속됩니다. 같은 네트워크의 다른 PC에서는 열리지 않습니다.

2. 화면 구성

상단 바대상 고르기 · ＋ 대상 추가 · 다시 분석 · 코드 열기(편집기 선택) · 보기 아이콘 8개 · 신선도 배지(● 최신) · 비교 · 보고서 · 분석 규모 · 못 본 것 N
진입점 목록패킷 핸들러, 레인 메시지, main, 단위 테스트 등. 폴더(프로세스) ▸ 클래스 트리로 묶여 있고, 종류로 거르고 검색할 수 있습니다.
보기호출 트리, 노드 그래프, 여정, 요약 등. 상단 아이콘으로 바꿉니다.
코드 스택진입점부터 고른 함수까지의 코드가 위에서 아래로 쌓입니다.

노드 그래프나 흐름도처럼 그림이 큰 보기에서는 그림이 위, 코드가 아래로 배치됩니다.

  • 칸 크기: 칸 사이 경계선을 끌면 너비(위아래 배치에서는 높이)가 바뀝니다. 두 번 누르면 기본 크기로 돌아가고, 바꾼 크기는 브라우저가 기억합니다.
  • 바뀐 줄 보기: 비교 기준(직전 분석이나 저장한 기준)과 본문이 다른 함수는 칸 제목 줄에 바뀐 줄 보기가 생깁니다. 누르면 지운 줄은 빨강, 더한 줄은 초록으로 보입니다. 비교 패널의 "함수 삭제"를 누르면 지워진 함수를 기준 코드로 볼 수 있습니다.
  • 검토 표시: 함수 칸 아래 ✓ 확인 보류와 메모. 진입점 옆에 "확인/닿는 함수" 진행률이 붙고, 확인한 뒤 본문이 바뀌면 "다시 봐야 함"이 됩니다. 기록은 data\<대상>\review.json에 남습니다.
  • git 변경: 비교 패널의 git 변경 보기는 작업 폴더와 마지막 커밋을 비교해, 바뀐 줄이 걸린 함수와 어떤 흐름에도 안 걸린 변경(등록 코드·헤더·설정 등)을 보여 줍니다. git은 읽기만 합니다.
  • 진입점 트리: 왼쪽 목록은 폴더(프로세스) ▸ 클래스 ▸ 진입점입니다. 폴더와 클래스 이름을 누르면 접고 펼치며, 오른쪽 숫자는 그 안의 진입점 수입니다. 검색 중에는 찾은 것이 숨지 않게 모두 펼쳐집니다.
  • 종류 필터: 검색칸 아래 패킷 메시지 시작 테스트 함수 버튼으로 진입점 종류를 거릅니다. 여러 개를 함께 켤 수 있고, 다 끄면 전체가 보입니다. 종류가 하나뿐인 대상에서는 숨겨집니다. 종류는 진입점 규칙의 kind(없으면 규칙 이름으로 추정), 메시지 통로는 crossProcess로 정합니다.
  • 함수 검색: 왼쪽 검색칸에 함수 이름을 두 글자 이상 치면 진입점 아래에 "함수" 결과가 나옵니다. 누르면 그 함수에 닿는 진입점 목록이 열리고, 진입점부터 그 함수까지의 코드가 코드 스택에 쌓입니다.
  • 뒤로/앞으로: 상단 ← →(또는 Alt+←/→, 마우스 뒤로 단추)로 직전에 보던 진입점·경로로 돌아갑니다. 새로 고침해도 마지막에 보던 위치가 다시 열립니다.
  • 문법 색칠: 코드 스택의 키워드·문자열·주석·숫자에 색이 붙습니다. 눈으로 읽기 위한 것이라 매크로가 많은 줄은 틀릴 수 있지만 코드 글자는 그대로입니다.
  • 노드 보기: 선의 숫자는 호출한 줄 번호입니다. 노드를 끌면 그 아래 호출도 같이 움직이고, 화면 맞춤은 처음 배치(소스 순서)로 되돌립니다. "N줄" 묶음 상자(또는 안의 함수)를 누르면 그 줄이 코드 칸에서 열리고, 들어갈 함수는 줄 아래 호출 단추로 고릅니다.
  • 기본 화면으로: 왼쪽 위 ⌂ 홈을 누르면 대상 추가·비교·보고서 같은 열린 창이 닫힙니다. 대상 추가 화면에서는 ← 돌아가기나 보기 아이콘으로도 돌아갑니다.

3. 기본 사용: 흐름 읽기

  1. 상단에서 대상(예: asio-server)을 고릅니다. 처음이거나 코드가 바뀌었으면 다시 분석을 누릅니다.
  2. 왼쪽에서 진입점을 누릅니다. 가운데에 호출 트리가 나옵니다.
  3. 트리에서 함수를 누르면 오른쪽 코드 스택에 진입점부터 그 함수까지의 경로가 쌓입니다.
  4. 코드 안의 호출 줄을 누르면 그 함수가 아래에 한 단계 더 붙습니다. ✕ 아래 닫기로 그 아래를 지웁니다.
  5. 고치고 싶은 곳은 열기나 줄 번호를 누릅니다. 상단에서 고른 편집기(Visual Studio 또는 VS Code)가 그 줄에서 열립니다.

키보드도 됩니다. 트리에서 Enter는 열기, ←/→는 접기와 펼치기입니다.

표시 읽는 법

표시뜻
추정소스에서 직접 확인되지 않은 연결입니다. 예: 디스패처에 등록한 핸들러, 가상 함수의 구현 후보, 메시지(레인)를 거친 호출
멈춤: 정의 없음선언만 있고 본문을 찾지 못했습니다. 인터페이스나 함수 포인터로 부르는 경우가 많습니다.
외부분석 범위 밖(표준 라이브러리, 외부 라이브러리)이라 들어가지 않았습니다.
못 본 것 N분석이 놓친 부분 목록입니다. 결과를 믿기 전에 한 번 열어 봅니다.
N줄 묶음한 문장에서 이어 부른 호출(a().b()->c())입니다. 트리와 노드 보기에서 점선 상자 하나로 묶이고, 노드 보기에서는 선도 하나만 그어집니다. 추정 연결은 묶지 않습니다.
파란 줄 ▶코드 칸에서 아래 칸으로 이어지는 호출 줄입니다. 줄 아래 호출 단추 중 따라 들어간 함수도 파랗게 표시됩니다. 노랑은 다른 호출이 있는 줄입니다.

4. 보기 8가지

보기쓸 때
트리 보기기본 보기입니다. 진입점부터 호출을 들여쓰기 트리로 보여 줍니다. 모두 펼치기와 접기가 있습니다.
노드 보기같은 호출을 그래프로 봅니다. 화면 맞춤이 있습니다.
노드 크게그래프를 넓게 보고, 코드는 아래에 둡니다.
패킷 여정이 패킷을 누가 보냈는지(프로세스, 함수, 줄), 중간에 어디를 거쳤는지, 여기서 보낸 패킷이 어느 프로세스의 어느 핸들러로 가는지 보여 줍니다.
흐름 요약표시(설정, 스레드, 등록, 네트워크, DB, 캐시, 작업 단위)가 붙은 호출만 소스 순서대로 보여 줍니다. main에서는 시작 순서를, 핸들러에서는 DB·캐시 접근 순서를 봅니다.
전체 흐름도프로세스와 클래스로 그린 지도입니다. 클래스 사이 호출 수와 프로세스를 넘는 패킷이 보이고, 고른 진입점이 거치는 클래스만 밝게 표시됩니다.
클래스 다이어그램흐름에 나온 클래스의 부모 클래스와 멤버를 보여 줍니다.
점검 규칙설정한 규칙(락 안 I/O 등)에 걸린 곳을 보여 줍니다. 6장에서 설명합니다.

5. AI가 고친 코드 리뷰하기

  1. AI에게 코드를 고치게 하기 전에 비교 → 지금 결과를 기준으로 저장을 누릅니다.
  2. AI가 코드를 고치면 30초 안에 신선도 배지가 ● 바뀜 N으로 바뀝니다. 배지를 누르면 바뀐 파일이 보입니다. 다시 분석을 누릅니다.
  3. 비교를 열면 늘거나 준 진입점, 바뀐 함수(본문, 시그니처, 추가, 삭제), 바뀐 호출이 나옵니다. 공백이나 주석만 바뀐 함수는 세지 않습니다.
  4. 바뀐 함수를 누르고 영향을 보면, 그 함수를 거치는 패킷과 경로가 나옵니다. 경로를 누르면 코드 스택으로 읽을 수 있습니다.
  5. 이상한 곳은 열기로 편집기에서 고칩니다.
배지 뜻: 최신은 분석에 쓴 파일이 지금과 모두 같다는 뜻입니다. 바뀜 N은 N개 파일이 바뀌었다는 뜻입니다. 확인 불가는 예전 형식이라 지문이 없다는 뜻이며, 다시 분석하면 없어집니다. 배지는 확인만 하고 분석을 직접 돌리지는 않습니다.

6. 점검 규칙

상단의 방패 아이콘(점검 규칙)을 누르면 규칙마다 상태(돌았음, 꺼짐, 오류)와 지적 목록이 나옵니다.

  • 지적을 누르면 진입점부터 그곳까지의 경로가 코드 스택으로 열리고, 근거 줄이 강조됩니다.
  • 지적마다 확실도가 붙습니다. 높음은 그 자리에 직접 호출이 있다는 뜻이고, 보통은 아래 함수 안에서나 이름 표시로 판단했다는 뜻입니다. 낮음은 추정 연결을 지나서 찾았다는 뜻입니다.
  • 위쪽 확실도 높음·보통·낮음 단추로 보고 싶은 확실도만 남길 수 있습니다.
  • "고른 진입점만"을 켜면 지금 고른 진입점의 경로에 있는 지적만 남습니다.
  • 규칙은 targets\<이름>.json의 checks에서 고칩니다. 고친 뒤에는 다시 분석 없이 다시 점검만 누르면 됩니다.
규칙 종류찾는 것예
forbidInScope어떤 범위 안에서 부르면 안 되는 것을 부름락 안에서 DB·네트워크 I/O
requireWithin반드시 거쳐야 할 함수를 거치지 않고 닿음작업 단위나 레인 밖에서 게임 상태 변경
orderA 다음에 B를 하는데, 되돌리는 C가 없음재화 차감 뒤 지급하는데 실패 시 되돌리기가 없음
dependency이 폴더가 저 폴더를 부르거나 #include함공용 라이브러리가 서버 콘텐츠에 의존
지적은 "여기를 보라"는 뜻이지 판정이 아닙니다. 지적이 없다는 것도 "문제가 없다"가 아니라 "찾지 못했다"는 뜻입니다.

7. 문맥 복사와 AI 질문

  • 문맥 복사: 코드 스택 위 버튼을 누르면 진입점부터 지금 함수까지의 경로, 코드, 호출 근거(파일:줄), 추정 연결, 못 본 것이 Markdown으로 복사됩니다. 코드 포함을 끄면 함수 이름과 파일:줄 같은 구조만 복사됩니다.
  • AI에게 질문: AI(Claude Code 또는 Codex)를 고르고 질문을 쓴 뒤 보내기를 누르면, 같은 문맥을 붙여 질문하고 답을 화면에 실시간으로 보여 줍니다. 실패 처리, 스레드, 입력 검증, 설명 같은 자주 묻는 질문은 버튼으로 있습니다. 중단으로 멈출 수 있습니다.
  • AI는 보내기를 누를 때만 실행됩니다. AI는 대상 폴더를 읽기만 하고 파일을 고치지 않습니다. claude나 codex 명령이 PATH에 있어야 목록에 나옵니다.
회사 코드: AI에 질문하면 코드가 AI 서비스로 전송됩니다. 회사 PC에서는 회사의 AI 사용 규정을 먼저 확인하세요.

8. 공유 보고서

  1. 상단 보고서를 누릅니다.
  2. 범위(고른 진입점 또는 전체 진입점)와 넣을 항목(호출 트리, 패킷 여정, 흐름 요약, 점검)을 고릅니다.
  3. 만들기를 누른 뒤 복사하거나 내려받기(.md)를 누릅니다.

기본값은 소스 본문과 절대 경로를 뺀 구조만 담은 보고서입니다. "소스 본문 포함"을 켜면 경고가 나옵니다.

9. 대상 추가와 설정

  1. ＋ 대상 추가를 누릅니다. 폴더를 고르고 이 폴더로 설정 만들기를 누릅니다.
  2. 찾은 진입점 규칙과 예시를 확인하고, 필요 없는 규칙은 끕니다.
  3. 저장하고 분석을 누릅니다.
  • 폴더에 C++ 소스(.cpp, .h, .vcxproj)가 있으면 C++로, 없고 .csproj가 있으면 C#으로 봅니다.
  • 단위 테스트: gtest의 TEST(Suite, Name)(TEST_F, TEST_P)를 찾으면 "gtest 테스트" 규칙을 켭니다. 테스트 묶음(Suite)이 클래스로 보이고, 테스트가 부르는 라이브러리 함수 흐름을 따라갑니다. C#은 테스트 폴더를 기본으로 빼므로, 테스트를 보려면 exclude에서 빼고 진입점 규칙을 적습니다.
  • CMake 프로젝트의 빌드 폴더(build, out 등)에 생긴 .vcxproj와 .cpp는 분석 범위에서 뺍니다. include 경로는 cpp.extraIncludeDirs에 적습니다(테스트를 보려면 gtest 헤더 경로도).
  • 설정은 targets\<이름>.json에 저장됩니다. 자동으로 찾은 것이 틀리면 이 파일을 직접 고칩니다. 키 설명은 README의 "대상 추가" 장에 있습니다.
  • 분석 대상 폴더에는 아무것도 쓰지 않습니다. clangd 색인과 결과는 모두 data\<이름>\에 생깁니다.
data\에는 대상 소스 코드가 들어 있습니다. 회사 코드로 만든 결과는 회사 PC 밖으로 가져가지 마세요.

12. 문제 해결과 한계

증상해결
고친 화면이 안 바뀜서버가 떠 있는 동안 빌드하면 DLL이 잠겨 예전 버전으로 뜹니다. 서버를 끄고 dotnet build에서 오류 0을 확인한 뒤 다시 실행하세요.
C++ 다시 분석 실패clangd --version이 되는지, Visual Studio C++ 도구가 설치되어 있는지 확인하세요.
편집기 목록이 비어 있음Visual Studio(vswhere로 찾음)나 VS Code(code가 PATH에 있어야 함)가 없을 때입니다.
AI 목록이 비어 있음claude나 codex CLI가 PATH에 없을 때입니다.
호출이 빠져 보임못 본 것을 먼저 확인하세요. 아래 한계 때문일 수 있습니다.

알려진 한계

  • 정적 분석입니다. 가상 함수, std::function, 함수 포인터 너머는 "추정"이거나 "정의 없음"으로 보입니다.
  • C++에서 람다 안의 호출과 템플릿 생성자 호출은 clangd가 알려 주지 않아 빠집니다.
  • 패킷 여정, 메시지 연결, 흐름 요약 표시, 점검은 이름과 소스 텍스트 규칙(정규식)으로 만든 추정입니다.
  • 매크로가 만든 함수(gtest TEST)는 clangd가 답하지 않아, 본문의 호출 위치마다 정의를 따라가 찾습니다. 매크로 안에서 일어나는 호출(ASSERT(...) 안쪽 등)과 람다 안 호출은 빠질 수 있습니다.
  • C#은 NuGet 패키지 안의 형식을 풀지 못합니다. 그 호출은 빠지거나 "외부"로 보입니다.
